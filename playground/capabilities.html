Editing a chart, by instruction

A change is an operation with an inverse, not a regeneration: undo is free and a correct spec cannot be broken by "make the bars teal".

  • add_annotation — Drop a text callout at a data position.
  • add_reference_line — Add a target/threshold rule — the single most-requested chart annotation.
  • add_series — Add a second measure as its own layer — the dual-measure shape.
  • aggregate — Set an aggregate on a channel (sum, mean, count, …).
  • apply_config — Merge a ``config`` block — how a theme reaches the spec.
  • bin_field — Bin a quantitative field — turns a scatter into a histogram.
  • drop_series — Remove a layer by index, collapsing back to a unit spec when one remains.
  • facet_by — Small multiples — one panel per value of ``field``.
  • group_by — Side-by-side grouping via ``xOffset`` — the grouped-bar shape.
  • limit_top_n — Keep only the top (or bottom) N rows.
  • resolve_scale — Share or separate scales across layers/facets — the dual-axis switch.
  • set_axis — Adjust axis presentation. ``None`` leaves a property untouched;
  • set_color_field — Colour marks by a column — the usual way to add a series breakdown.
  • set_mark — Change the mark type, preserving mark properties where they still apply.
  • set_palette — Recolour the chart.

  • set_size — Set width/height. Always root-level: sizing a single layer is a bug.

  • set_tooltip — Set the hover tooltip. An empty ``fields`` list turns tooltips off.

One instruction, several actions

The manager reads free text and answers with ordered steps: edit, theme, narrate, place, widget, recreate, decline. What it cannot do — a breakdown needing data that is not in the rows — it declines, with the reason.

Arranging and theming

Widget layouts: executive_summary, kpi_row_plus_grid, single_column, two_column_grid. Themes: carbon-g90, nexcraftviz-dark, nexcraftviz-light, powerbi — applied after generation, so a hard-coded colour never defeats them.

Whole dashboards, as workflows

Declared in a skill file: a person picks and approves, the host queries and publishes.

  • Build a dashboard that answers a question
    dashboard.suggest_questions → select (a person) → host.query → workflow.build_widget → dashboard.layout → approve (a person) → host.publish
  • Arrange widgets I already have
    dashboard.layout → approve (a person) → host.publish
  • Add a narration, a table or another chart to a widget
    widget.narrate → widget.table → host.query → chart.create → widget.extend
