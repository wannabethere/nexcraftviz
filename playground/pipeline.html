The gap between the two lines is the story. A widening gap early is a scope problem; a flat stretch mid-sprint usually means work is blocked rather than slow.

When to use it
  • Question uses 'burndown', 'sprint', 'remaining', 'on track to finish'
  • One row per day with work still outstanding
  • There is a fixed end date the work is measured against

Not this chart when:

  • Asking how much was delivered, not how much is left → bar
  • No day-by-day history, only a current total → gauge
  • Work moving between states rather than shrinking → cumulative_flow

Read the width of each band, not the lines. A band that stays wide is a queue; the one that widens is where work is arriving faster than it leaves.

When to use it
  • Question uses 'cumulative flow', 'bottleneck', 'where is work stuck', 'wip'
  • One row per day per state, with a count
  • Items move between states rather than simply completing

Not this chart when:

  • Only remaining work matters → burndown
  • A single point in time, not a history → stacked_bar
  • Stages are strictly one-way with drop-off → funnel

Look for the overlaps. Where two bars meet is where a slip in the first eats the float in the second — those joins are the schedule's real risk, not the longest bar.

When to use it
  • Question uses 'schedule', 'timeline', 'plan', 'gantt', 'when does'
  • Each row has a start AND an end date
  • Between 3 and 30 tasks

Not this chart when:

  • Rows are single dates, not ranges → milestone_timeline
  • Only percentage complete matters, not dates → bullet
  • More than about 30 tasks — the labels stop being readable

When to use it

  • Each row is one date, not a range
  • Under about 12 points, or the labels collide

Not this chart when:

  • Rows span a start and an end → gantt
  • A measure changes over the dates → line

When to use it
  • Question uses 'budget', 'burn rate', 'spend remaining', 'runway'
  • One row per period with the amount still unspent
  • There is a planned end date the spend is measured against

  • Comparing spend across projects → bar
  • Spend by category at one moment → donut
  • Only the current figure against a target → bullet

The first long bar is usually access provisioning, and it delays everything after it — shortening it moves the whole ramp left.

When to use it
  • Question uses 'onboarding', 'ramp', 'time to productivity'
  • Each step has a start AND an end date
  • One person or one cohort, not a whole population

Not this chart when:

  • Comparing ramp length between people → bar

A band that keeps widening is a stage without enough interviewer capacity — the constraint is people's calendars, not the number of applicants.

When to use it
  • Question uses 'pipeline over time', 'where are candidates stuck'
  • One row per period per stage, with a count
  • The same candidates move between stages week to week

Not this chart when:

  • A single snapshot of the funnel → funnel
  • Only the conversion rate matters → kpi
